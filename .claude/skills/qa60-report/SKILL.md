# 60QA 形式の報告

実験の結果を、論文の骨組みになる質問への回答として並べ直す手順。元は慶應義塾大学 杉浦孔明研究室の「60 Questions & Answers」で、標準的な国際会議論文の約 60 段落を、1 段落 ＝ 1 つの質問への回答として書く仕組みである。本研究用に質問を改良してある（[references/questions.md](references/questions.md)）。

読み手は 3 人いる。研究の判断をするユーザー本人、回答を確認する指導教員、後で論文の段落に書き直すときの自分。3 人とも、「この質問に今の結果で答えられるか。答えられないなら何が足りないか」を知りたい。そのため、答えられない質問を推測で埋めず、▲ のまま足りないものを書くことが、このスキルで最も大事な決まりになる。

`experiment-report` との分担は次のとおり。

| | experiment-report | qa60-report（このスキル） |
| --- | --- | --- |
| 単位 | 実験 1 つ | 研究全体（その時点の進捗） |
| 並べ方 | 結論 → 設定の差分 → 結果 → 評価 → 次の手 | 論文の章と質問の順 |
| 役割 | 数値・図・再現コマンドの記録 | 論文の段落の下書きと、足りないものの一覧 |

数値はこのスキルで新しく作らない。`experiment-report` の報告書と採点 CSV から取り、回答ごとに出所を書く。

> **ScheduleAgent での注意（2026-11-18 に DomainTransfer_trial から写した）**
> - `experiment-report` のスキルと `report_numbers.py` はこのリポジトリにまだ無い。数値は `outputs/llm_memory_trial/<stem>/summary.csv`・`curve.csv`・`participation.csv` から取る
> - [references/questions.md](references/questions.md) の「答え方」「根拠」の列は論文 P（2 段階学習）向けに書いたまま。論文 L の回答の軸は `docs/YYYY-MM-DD_paper_skeleton.md` のうち最も新しいものから取り、P 向けの答え方（2 段階学習・事前学習損失など）は使わない
> - 下の 5 章「用語」は P の用語。L に関係する行（活動スケジュール・集計表・集計量・群）だけを使う

## 2. 手順

1. **報告の範囲を決める。** どの実験の結果をまとめるのかを確かめる（モデル・比較手法・種・日付）。これが 0-1 の回答になる。曖昧ならユーザーに聞く。
2. **前回の QA を読む。** 範囲が「全体」の回答は前回から引き継ぎ、根拠が変わったものだけ直す。ユーザーや教員が付けた記号（△ ○ □ ◎）と、その回答の文は書き換えない。根拠の数値が変わって書き換えが要るときは、記号を ▽ に戻し、「前回から」に理由を書く。
3. **材料が新しいことを確かめる。** 採点 CSV が ckpt や生成物より古くないかを、`experiment-report` の `report_numbers.py fresh` で見る。結果の報告書がまだ無い実験は、先に `experiment-report` で報告書を作るか、`report_numbers.py compare` の出力を直接使う。
4. **回答を書く。** 書く順は 3 → 5 → 4 → 6 → 7 → 1 → 2 → 0 にする。問題設定と用語（3 章）を先に固めないと、同じ直しが後ろの回答すべてに及ぶ。序論と要旨は、結果が決まってからでないと主張の強さを決められない。ファイルの中の並びは 0 章から 7 章の順にする。
   - **2 章は 2-5 から書く。** 2-5（関連研究群の整理と本研究の位置）で軸と表を先に決め、その表に合わせて 2-2 の分野の分け方と 2-4 の類似手法を決める。1-5・1-7・4-3 の「違い」の言い方も 2-5 から取り、4 か所で食い違わないようにする。軸は質問一覧で固定していないので、前回の QA の軸を引き継ぐか、変えるなら 0-1 の「前回から」に理由を書く。
   - **2-2 は書くときに増やす。** 質問一覧の 2-2 は「N 個目の関連分野を説明せよ」の 1 問だけである。2 個目以降の関連分野の数だけ 2-2a、2-2b、… と回答を作り、見出しを「2 個目の関連分野（分野の名前）」の形にする。分野は論文のドラフトの関連研究の段落と wiki から決め、前回の QA があればその分け方を引き継ぐ。分野を増やす・減らす・分け直すときは、0-1 の「前回から」に書く。報告書に `2-2` そのものの見出しは作らない。
5. **ファイルに書く。** `docs/qa60/QA60_YYYYMMDD_<内容>.md`。前回のファイルは上書きせず、日付の違う新しいファイルにする（進捗ごとの写しを残す）。
6. **日本語を仕上げる。** CLAUDE.md に従い、natural-japanese のスキルを使う。lint は、回答の書き出しの繰り返し（「本研究は」「SA は」「1 つ目は」）を多数指摘する。回答は 1 つずつ独立した段落で、第 1 文を主語から始める決まりなので、この指摘は残してよい。
7. **確かめる。** ID の抜けと重複を調べ、完了率の表を報告書に書き込む。

   ```bash
   .venv/bin/python .claude/skills/qa60-report/scripts/qa_check.py docs/qa60/QA60_YYYYMMDD_<内容>.md --write
   ```

8. **ユーザーへの返答** は、完了率（章ごとの数）、▲ の質問と足りないもの、判断が要る点だけにする。回答の全文は報告書に任せる。

## 3. 回答の書き方

元のシートの決まりと、このリポジトリで決まったことを合わせてある。

### 元のシートの決まり

- 質問者は査読者（他大学・他分野の教員）と考える。機械学習に詳しくない読み手にも通じる言葉で書く。
- 回答の第 1 文は、トピックセンテンスから始める。長い説明の前には、説明が始まることを先に述べる。
- 5 章から後ろは過去形で書く。
- 1-5：既存手法を 1 つだけ挙げない。複数の手法の不足を抽象化して書く。
- 6-1：表の行と列の意味、数値が何か（平均・中央値・範囲）、何回実験したかを書く。
- 6-6：結果の説明で同じ文型を繰り返さない。
- 6-8：第 1 文で「表（図）に…を示す」と書く。結果を並べるだけでなく、どの点が適切だったかと、その根拠を書く。
- 6-10：取り除いたモデルを Model (i)、(ii) と呼ぶ。提案手法は (i)(ii) のどれでもない。

### このリポジトリの決まり

- **回答は短い段落 1 つ（2〜5 文）。** 数値が 3 つ以上なら表にする。前提の言い換えや、同じ注意書きの繰り返しは書かない。
- **数値には出所を付ける。** 手で写さず、`report_numbers.py` の出力か報告書の表から取る。
- **種が複数なら [最小, 最大]、種 1 つなら「種 42 だけ・暫定」** と書く。検定をしていない差を「有意」と書かない。
- **加重は尺度ごとに書く。** 集計表との誤差は日本の推定人口、個人の 1 日の尺度は ATUS の群構成。
- **事実と推定を分ける。** 介入で確かめていない原因は「推定」と書く。
- **判定の規則と予測は、結果を見る前に決めたものだけを使う**（6-16）。
- **図は Mermaid を少なくとも 1 つ入れる**（1-10 か 4-4）。図の変数名はコードと同じにする（`a_hat`・`a_star`・`l_agg`・`l_reh`）。画像の図は既存のものを相対パスで貼り、新しく作るなら `experiment-report` の置き場所に従う。

## 4. 記号

| 記号 | 意味 | 誰が付けるか |
| --- | --- | --- |
| ▲ | 未完了。根拠が足りず回答できない（足りないものを書く） | Claude |
| ▽ | 下書き。根拠つきで書いたが、本人は未確認 | Claude |
| △ | 本人が確認済み（日本語） | ユーザー |
| ○ | 教員が確認済み（日本語） | ユーザー |
| □ | 確認済み（英語） | ユーザー |
| ◎ | 教員が確認済み（英語） | ユーザー |

▽ は元のシートに無い記号で、Claude の下書きを確認済みの回答と区別するために足した。Claude が付けてよいのは ▲ と ▽ だけである。

▲ にするのは、たとえば次のとき。

- 要る実験をまだ回していない（アブレーション、種の追加）
- 測っていない量を聞かれた（生成 1 人分の時間、FLOPs）
- 結果はあるが、主張を決める判断がユーザーに残っている（判定の指標、比較手法の扱い）

▲ と ▽ は、質問の中心に答えられたかで分ける。中心に答えられないときは、書ける部分を書いたうえで ▲ にし、残りを「足りないもの」に書く。中心には答えられて細部だけが足りないとき（例：統計の表のうち 1 行が未集計）は ▽ にし、足りない細部を「足りないもの」に書く。

## 5. 用語

QA は論文の骨組みなので、論文の用語で書く。リポジトリの報告書の言葉と違うものがある。

| 論文の用語（QA で使う） | リポジトリの報告書・コード | 補足 |
| --- | --- | --- |
| 活動スケジュール、「〜人分」 | 日誌、「〜本」 | 「日誌」は使わない |
| 集計表（公表）／個票（公開） | 教師・公表統計／個票 | 生成物から計算する量は「集計量」 |
| 事前学習損失 $L_{\mathrm{pre}}$ | リハーサル損失 `l_reh` | 「リハーサル項」は使わない |
| 第二段階の学習 | Stage 2・微調整 | モデルの名前としての Fine-tuned は使う |
| Pre-trained／Fine-tuned | E0（`zeroshot`）／E1（`all`） | zero-shot と書かない |
| $A^{*}_{d,c,s}$・$\tilde{A}_{d,c,s}$ | `a_star`・`a_hat` | 対応は 3-6 に 1 度書く |
| 群 $d$、社会属性、就業状態 | 群、条件 | |
| 全国値 | 全国の時刻別曲線 | 28 群を推定人口で加重した時刻別行動者率 |
| 時刻符号 | 時計・clock | |
| 過学習 | 暗記 | |

英語にするのは、ユーザーが頼んだときだけ。訳語は `Write/Conferences/CLAUDE.md` の「英訳」に従う。0-1・6-16・7-5 は論文の段落にならないので、英語にしない。

## 6. 質問を変えるとき

質問の追加・削除・文言の変更は、[references/questions.md](references/questions.md) と [references/changes-from-original.md](references/changes-from-original.md) を一緒に直し、版の日付を更新する。`docs/based/QA60_questions.md` は questions.md の写しなので、同じ内容に直す（違うのは冒頭のリンクの行だけ）。ID は使い回さない（削った ID を別の質問に付けない）。`qa_check.py` は questions.md の表から ID を読むので、表の先頭 2 列（`| ID | 範囲 |`）の形は変えない。

## 7. よくある落とし穴

- **種 1 つの結果で序論を書く。** 1-9・0-2・7-2 は 6 章の回答より強く書かない。6-7 が ▲ のあいだは、主張に「暫定」を付ける。
- **SA と教師への適合だけで比べる。** SA は時刻別行動者率を構成上満たすので、集計表との誤差は必ず最小になる。主張は 6-15（学習に使っていない量）で支える。
- **評価の本数の違い。** SA の群あたりの人数がほかの手法と違うときは、6-1 の表の下に書く。
- **生成器の間で改善幅を比べる。** λ を掛ける損失の単位が生成器ごとに違う。比べるのは各生成器の中の Pre-trained → Fine-tuned で、生成器どうしの順位は主張にしない。
- **論文のドラフトの数値をそのまま写す。** ドラフトの数値は別の設定（種 5 つの中央値など）のことがある。今回の報告の範囲と違う数値を使うときは、出所と設定を書く。
- **位置づけで網羅性を主張する。** 2-5 の表は調べた範囲の整理であり、「初めて」「ほかに無い」とは書かない。全文を読んでいない論文は表に入れず、「足りないもの」に挙げる。
- **古い採点 CSV を読む。** `experiment-report` の落とし穴（生成プールの取り違え・印の取り違え）がそのまま当てはまる。
