# 元の 60QA から変えたこと

元のシートは「テンプレの質問は最大公約数なので、通常 10 個程度はカスタマイズか削除する」としている。本研究（他国の個票と対象国の集計表から活動スケジュールの生成器を学習する）に合わせて、次のように変えた。質問を変えたいときは、[questions.md](questions.md) とこのファイルを一緒に直す。

## 1. 数

| | 元の 60 問のうち | 本研究用の ID の数 |
| --- | --- | --- |
| そのまま残した | 45 | 48（4-8 を a〜d に分けた） |
| 文言を変えた | 14 | 14 |
| 削った | 1 | 0 |
| 足した | — | 9 |
| 合計 | 60 | 71 |

2-2 と 4-8 は、元のシートが「個数分コピーしてください」としている質問である。

- **2-2（N 個目の関連分野）：** 元の文言のまま 1 問にしてある（2026-11-16 のユーザーの判断）。関連分野の分け方を質問一覧で固定せず、報告書を書くときに分野の数だけ 2-2a、2-2b、… と増やす。そのため、報告書の問数は 71 より多くなる
- **4-8（N 個目の構成要素）：** 手法の 4 つの構成要素に対応させ、質問一覧の中で a〜d に分けてある

## 2. 文言を変えた質問（14 問）

| ID | 元の質問 | 変えた後 | 理由 |
| --- | --- | --- | --- |
| 2-3 | 標準ベンチマーク群について説明せよ | 分野で使われるデータと評価の慣行。標準ベンチマークが無いことをどう補うか | 活動スケジュールの合成には、共通のベンチマークが無い |
| 4-5 | 主要モジュールの数と名称 | 主要な構成要素（段階・損失）の数と名称 | 新しさがネットワークの部品ではなく、学習の段階と損失にある |
| 4-7 | 入力特徴の抽出（バックボーン） | 条件（群）と時刻の符号化 | 画像や言語のバックボーンを使わない。入力は社会属性と時刻 |
| 4-9 | 予測を数式で定義せよ | 生成（サンプリング）と集計量を数式で定義せよ | 出力は予測値ではなく標本と、その集計量 |
| 5-3 | データセットの構築方法（アノテーション） | 2 つの調査の対応づけ（活動分類・群・起点・教師の作り方） | アノテーションは行っていない。代わりに、調査の間の対応づけが結果を左右する |
| 5-5 | 統計情報（語彙サイズ・文長など） | 回答者数・群ごとの人数・活動の割合・切り替え回数・集計表の標本の大きさ | データが言語や画像ではない |
| 5-9 | パラメータ数と FLOPs | パラメータ数と、生成 1 回の計算量 | 生成器ごとに生成の手順が違う（自己回帰 96 ステップ、逆過程 1,000 ステップ） |
| 5-11 | 訓練時間と 1 サンプルあたりの推論時間 | 訓練時間と、活動スケジュール 1 人分の生成時間 | 推論ではなく生成。SA は訓練と生成が分かれない |
| 6-7 | 統計的に有意（p < 0.05）か | 差は、種によるばらつきの範囲を超えているか | 検定をしていない結果に「有意」と書かないため。検定をしたときは方法を書く |
| 6-8・6-9 | Ground Truth・ベースライン・提案手法の予測 | 集計表・ベースライン・提案手法の値 | 日本の個票が無いので、個人単位の正解は無い |
| 6-11 | 混同行列を示せ | 誤差の内訳を、活動ごと・群ごとに示せ | 分類のタスクではない。同じ役割（どこで間違えるか）を誤差の内訳で果たす |
| 6-12 | 失敗例は合計何サンプルあったか | 第二段階の学習で誤差が増えた群・活動はいくつあったか | 失敗を数える単位がサンプルではなく、群と活動 |
| 6-13 | 失敗例を人手でカテゴリに分類せよ | うまくいかなかった例を型に分類せよ | 同上。型は生成物の性質（細切れ・割合のずれなど）で定義する |

6-8 と 6-9 は 2 問として数えた。2-4 は文言を変えていないが、2-5 を足したので、答え方を「最も近い 2〜3 手法との仕組みの違い」に絞った。

## 5. 論文の段落にならない質問

0-1・6-16・7-5 は進捗の報告のための質問で、論文の段落には対応しない。完了率にも数えるが、英語にする工程（□・◎）からは外す。
