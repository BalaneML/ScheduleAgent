# 出力の雛形

ファイル名は `docs/qa60/QA60_YYYYMMDD_<内容>.md`（例 `QA60_20261118_memory_trial_gemma4.md`）。`docs/` は `.gitignore` の対象なので、コミットされない（ScheduleAgent でも同じ）。

見出しの形は `### 記号 ID. 質問` に固定する。`scripts/qa_check.py` がこの形だけを回答として数えるので、記号と ID の間・ID の後ろのピリオドを変えない。

````markdown
# 60QA 報告：<何の実験の結果かを 1 行で>

- **日付：** YYYY-MM-DD
- **対象の実験：** <実験の名前>（設定 [..](..)・結果 [..](..)）
- **前回の QA：** [..](..)（無ければ「初回」）
- **質問一覧：** `.claude/skills/qa60-report/references/questions.md`（版 YYYY-MM-DD）
- **記号：** ▲ 未完了 / ▽ 下書き（Claude が作成、本人は未確認）/ △ 本人が確認済み（日本語）/ ○ 教員が確認済み（日本語）/ □ 確認済み（英語）/ ◎ 教員が確認済み（英語）
- **想定する質問者：** 査読者（他大学・他分野の教員）

<!-- qa60:status:start -->
<!-- qa60:status:end -->

## 0. 前提・要旨

### ▽ 0-1. この報告は、どの実験のどの時点の結果をまとめたものか？

<回答。第 1 文はトピックセンテンス。2〜5 文か、表>

- **根拠：** <ファイルと節・CSV の名前>

### ▲ 0-2. 論文の要旨を 5 文で書け

<書けるところまで書く>

- **根拠：** …
- **足りないもの：** <何があれば回答できるか（実験・数値・判断）>

## 1. はじめに・序論

（以下、質問一覧の順に全問）
````

## 回答 1 つの形

| 部分 | 中身 |
| --- | --- |
| 見出し | `### 記号 ID. 質問`（質問は日本語だけでよい） |
| 回答 | 第 1 文はトピックセンテンス。論文の 1 段落になる長さ（2〜5 文）。数値が 3 つ以上なら表にする。5 章から後ろは過去形 |
| 根拠 | 回答の材料にしたファイルと節。数値は CSV の名前か報告書の節まで書く |
| 足りないもの | ▲ のときは必ず書く。▽ でも、回答の一部が未確定ならここに書く |
| 前回から | 前回の QA から回答が変わったときだけ、何が変わったかを 1 行で書く |

## 書くときに増やす質問（2-2）

質問一覧の 2-2 は 1 問だが、報告書では 2 個目以降の関連分野ごとに見出しを作る。`2-2` そのものの見出しは作らない。

```markdown
### ▽ 2-2a. 論文を複数挙げて、2 個目の関連分野（LLM で人の行動・移動を生成する研究）を説明せよ
### ▽ 2-2b. 論文を複数挙げて、3 個目の関連分野（LLM で集計量に合う合成データを作る研究）を説明せよ
```

「根拠」に書けるものが無い回答は、▽ にしない。推測で埋めず、▲ にして足りないものを書く。
